## DEF-001 高数值方块缺少配色

**模块：** 视觉 / 边界  
**级别：** P2（中）  
**状态：** 已修复  
**发现方式：** 边界测试 + CSS 代码审查

**前置条件：** 棋盘存在两个 8192 方块。

**复现步骤：**
1. 通过测试钩子设置棋盘：`[8192, 8192, 0, ...]`；
2. 向左移动，合并生成 16384；
3. 查看 16384 方块的背景色和文字。

**预期结果：** 16384 方块有明确背景色，数字清晰可读。  
**实际结果：** CSS 只定义了 2 ~ 8192 的配色，16384 及以上使用默认 `.tile` 样式，背景透明、文字与棋盘底色对比度不足，可读性差。

**根因：** 高数值配色覆盖不完整。

**修复：**
- 增加 `.tile-16384`、`.tile-32768`、`.tile-65536` 深色背景与白色文字；
- 增加回归用例 `test_high_value_tile_style`，断言背景色不是透明。

**回归结果：** 通过。

## DEF-002 localStorage 异常未捕获

**模块：** 健壮性  
**级别：** P2（中）  
**状态：** 已修复  
**发现方式：** 代码审查 + 异常注入测试

**前置条件：** 浏览器隐私模式/安全策略导致 `localStorage.getItem` 或 `setItem` 抛异常。

**复现步骤：**
1. 通过 CDP 注入脚本，让 `Storage.prototype.getItem` 和 `setItem` 抛异常；
2. 打开游戏页面；
3. 观察页面是否正常初始化。

**预期结果：** 页面正常加载并可继续游戏，最高分降级为 0。  
**实际结果：** 原实现直接调用 `localStorage.getItem`，异常会中断脚本初始化，棋盘和交互可能不可用。

**根因：** 没有对 localStorage 做异常兜底。

**修复：**
- 增加 `loadBest()` / `saveBest()`，用 try/catch 包裹读写；
- 失败时最高分降级为 0，不影响游戏核心玩法；
- 增加回归用例 `test_localstorage_unavailable`。

**回归结果：** 通过，页面正常加载，状态 playing，最高分 0。

## DEF-003 仅覆盖 Edge 视口（已知限制）

**模块：** 兼容性  
**级别：** P3（低）  
**状态：** 已知限制

**描述：** 当前自动化只覆盖 Microsoft Edge 桌面/移动视口，未覆盖 Chrome、Safari、Firefox 和真机。  
**影响：** 兼容性结论有限，不能声称“全浏览器兼容”。  
**建议：** 后续接入 Playwright/Selenium Grid 或云真机平台，补充多浏览器与真机矩阵。

---

## DEF-004 最高分仅本地存储（已知限制）

**模块：** 数据  
**级别：** P3（低）  
**状态：** 已知限制

**描述：** 最高分保存在 `localStorage`，清缓存、换浏览器或换设备后会丢失。  
**影响：** 不影响单机玩法，但不具备跨端同步能力。  
**建议：** 如产品需要，可增加账号体系与后端排行榜。

---

## 缺陷分析小结

- 2 个已修复问题分别属于**视觉边界**和**异常健壮性**，都不是核心算法错误；
- 合并/计分/胜负等核心逻辑通过 21 个自动化测试与 4 个方向参数化用例验证，未发现 P0/P1 缺陷；
- 已知限制主要是测试范围（Edge 视口）和数据存储方式，已在测试报告中明确说明，避免过度承诺。
