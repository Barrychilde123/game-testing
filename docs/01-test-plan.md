# 2048 网页游戏测试计划

## 1. 项目背景

本项目以一个可运行的 2048 网页游戏为被测对象，模拟游戏测试的核心工作：功能规则、状态迁移、边界场景、兼容性、性能、弱网、异常与稳定性。目标是用一套可复现、可自动化的测试资产，证明游戏测试的基本功与问题定位能力。

## 2. 被测系统

| 项目 | 说明 |
|---|---|
| 系统 | 2048 网页游戏（原生 HTML/CSS/JS） |
| 访问地址 | http://127.0.0.1:8001 |
| 运行方式 | `python -m http.server 8001` |
| 浏览器 | Microsoft Edge 155（Selenium 驱动） |
| 核心机制 | 4x4 棋盘、同值合并、计分、2048 胜利、无路可走失败、最高分 localStorage |
| 测试钩子 | `?seed=42` 固定随机种子；`window.__game` 提供 setBoard / move / getState |

## 3. 测试范围

### 3.1 范围内

- 移动与合并：上、下、左、右四个方向；2+2、2+2+2+2；分数累加。
- 状态与胜负：playing / won / over；胜利后继续游戏；棋盘填满无合并时失败。
- 最高分：localStorage 写入、刷新恢复、新游戏保留。
- 键盘与触屏：方向键、WASD、移动端滑动。
- 兼容性：320px / 375px 移动视口、1200px 桌面视口，无横向溢出。
- 性能：正常加载、3G 弱网加载、连续 200 次方向操作。
- 异常：localStorage 不可用时游戏仍可运行。
- 边界：高数值方块（16384）样式与可读性。

### 3.2 范围外

- 原生 App / Android / iOS 测试
- 服务端、数据库、支付、账号体系
- 多浏览器/真机兼容性（当前只做 Edge 视口）
- 安全渗透测试
- 音效、动画、撤销等体验功能

## 4. 测试策略

| 测试类型 | 方法 | 工具 |
|---|---|---|
| 功能测试 | 等价类、边界值、状态迁移、场景法 | 手工 + 自动化 |
| 合并逻辑 | 参数化构造棋盘，验证四个方向与得分 | pytest + JS 测试钩子 |
| 兼容性 | 320 / 375 / 1200px 视口，检查 scrollWidth 与棋盘宽度 | Selenium |
| 性能测试 | navigation timing、弱网 CDP、连续操作耗时 | Selenium + CDP |
| 异常测试 | 注入 localStorage 异常，验证降级 | Selenium + CDP |
| 缺陷管理 | 复现步骤、根因、修复、回归 | Markdown |

### 4.1 测试数据

- 固定 seed=42，保证开局与随机生成可复现。
- `window.__game.setBoard([...])` 直接构造目标棋盘，避免依赖随机开局。
- 每个自动化测试独立浏览器会话，避免状态污染。
- 最高分测试使用独立 localStorage 清理，避免跨用例影响。

## 7. 准入与准出

**准入：**
- 游戏页面可访问，核心规则可运行；
- 测试钩子（seed / setBoard / getState）可用；
- 测试用例评审通过。

**准出：**
- P0/P1 用例全部执行，通过率 ≥ 95%；
- 阻断性缺陷为 0；
- Allure 报告、性能数据、缺陷报告产出；
- 关键截图归档。

## 8. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 随机开局导致断言不稳定 | 用例 flaky | 固定 seed + setBoard 测试钩子 |
| 无头浏览器与真实设备差异 | 兼容性结论有限 | 明确只覆盖 Edge 视口，真机另行测试 |
| localStorage 状态污染 | 最高分用例互相影响 | 每个用例独立浏览器，必要时清空 localStorage |
| 弱网仅模拟带宽/延迟 | 与真实弱网有差异 | 记录模拟参数，结论标注为基线 |
| 游戏无后端 | 无法覆盖接口/服务端 | 明确范围，后续可扩展多人对战/排行榜接口 |

## 10. 缺陷分级

| 级别 | 定义 | 示例 |
|---|---|---|
| P0 / 严重 | 核心玩法不可用、数据错误 | 合并结果错误、分数计算错误 |
| P1 / 高 | 主要功能异常、无绕过 | 无法胜利/无法结束、最高分丢失 |
| P2 / 中 | 次要功能/兼容性异常 | 高数值方块不可读、小屏溢出 |
| P3 / 低 | 样式、文案、体验 | 提示语、动效 |
